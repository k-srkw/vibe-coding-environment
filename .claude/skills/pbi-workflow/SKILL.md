# PBI ワークフロー（ATDD + DoD）

PBI の着手から完了まで、Definition of Done に従った ATDD ワークフローを 5 フェーズで実行する。

引数として PBI 番号またはファイル名を受け取る（例: `/pbi-workflow 1` または `/pbi-workflow pbi-01-rhdh-local-setup.md`）。

## Phase 1: 着手準備

1. 指定された PBI ファイルを `docs/product-backlog/` から読み込む
2. ステータスが「未着手」であることを確認する
3. 依存 PBI のステータスがすべて「完了」であることを確認する
4. 依存 PBI の受け入れテストがリグレッションしていないことを確認する

いずれかが未達の場合、着手不可の理由を表示して停止する。

すべて OK の場合:
- PBI ファイルのステータスを「進行中」に更新する
- `docs/product-backlog/README.md` の一覧テーブルも「進行中」に更新する

## Phase 2: テスト先行（ATDD）

1. 受け入れ条件を 1 つずつ確認する
2. 各受け入れ条件に対して:
   - Gherkin シナリオに変換できるもの → `.feature` ファイルを作成する
   - テストが書けないもの → 手動確認手順を明記する
3. PBI ファイルの「受け入れ条件の検証方法」テーブルを埋める
4. ユーザーに `.feature` ファイルと検証方法テーブルの確認を求める

この時点ではステップ定義は未実装で OK。テストは Red（失敗）の状態。

## Phase 3: 実装

1. Plan モードで実装計画を立てる
2. Gherkin シナリオに対応するステップ定義と実装コードを作成する
3. `npm test` でテストを実行する
4. テストが全件 Green になるまで実装を繰り返す

## Phase 4: リファクタリング

テストが Green の状態を維持しながら、実装コードとテストコードの品質を改善する。

### 前提条件

- Phase 3 で全テストが Green であること
- リファクタリング中もテストが Green を維持すること（変更のたびに `npm test` で確認）

### 手順

1. 実装コードのリファクタリング観点を洗い出す
   - 重複コードの抽出・共通化
   - 関数・モジュールの責務分離（単一責任の原則）
   - 命名の改善（変数名、関数名、ファイル名）
   - マジックナンバーや文字列リテラルの定数化
   - 不要なコード（デッドコード、デバッグ用コード）の除去
   - エラーハンドリングの整理
2. テストコードのリファクタリング観点を洗い出す
   - Gherkin シナリオの可読性向上（Given/When/Then の表現の統一）
   - ステップ定義の重複排除と再利用性の向上
   - テストデータのハードコード排除（Scenario Outline / Examples の活用）
   - テストヘルパーやフィクスチャの共通化
3. 洗い出した観点に優先度をつけ、ユーザーに提示する
4. ユーザーの承認を得た観点からリファクタリングを実施する
5. 各変更のあとに `npm test` を実行し、全テストが Green のままであることを確認する
6. テストが Red になった場合はリファクタリングを取り消し、より小さな単位でやり直す

### AI 駆動開発での注意点

- リファクタリングは「振る舞いを変えない変更」に限定する。新機能の追加や仕様変更と混ぜない
- 変更の単位を小さく保ち、1 つの観点ごとにテストを実行する
- リファクタリングの意図をコミットメッセージに残し、後続の AI セッションでもコンテキストが伝わるようにする

## Phase 5: 完了判定（DoD チェック）

`docs/product-backlog/definition-of-done.md` を読み込み、以下を順番にチェックする:

### 1. ATDD サイクル
- [ ] 受け入れ条件に対応する Gherkin シナリオが存在する（または手動確認として登録済み）
- [ ] テストが全件 Green（テスト環境がある場合）

### 2. 受け入れ条件
- [ ] PBI ファイルの受け入れ条件が全件 `- [x]` チェック済み
- [ ] 検証方法テーブルが埋まっている

### 3. 成果物
- [ ] 「想定する成果物」のファイルがすべて存在する

### 4. リグレッション
- [ ] 既完了 PBI のテストが引き続き Green

### 5. コンテキスト更新
以下を実行する:
- PBI ファイルのステータスを「完了」に更新する
- `docs/product-backlog/README.md` の一覧テーブルを更新する
- 実装で得た知見があれば CLAUDE.md または関連ドキュメントに追記する

### 6. 完了証跡
PBI ファイルの「完了証跡」セクションに以下を記録する:
- テスト実行結果（シナリオ数、ステップ数、pass/fail）
- 確認日時
- 備考（手動確認した項目の結果等）

すべて OK の場合のみ、PBI を「完了」とする。NG がある場合は未達項目を一覧表示して停止する。
