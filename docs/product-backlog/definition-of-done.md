# Definition of Done (DoD) — AI 駆動開発版

## 概要

本 DoD はハーネスエンジニアリング（ATDD）とコンテキストエンジニアリングに最適化した完了基準である。すべての PBI はこの DoD を満たさない限り「完了」としない。

## DoD チェックリスト

### 1. ATDD サイクル

- [ ] 受け入れ条件に対応する Gherkin シナリオ（`.feature` ファイル）が存在する
- [ ] `.feature` ファイルが実装コードより先に作成されている
- [ ] `npm test` が全件 Green（exit 0）

> テスト環境がない段階（PBI-1 等）では、「受け入れ条件の検証方法」テーブルに「手動確認」と明記し、手動検証の手順と結果を完了証跡に記録する。

### 2. 受け入れ条件

- [ ] PBI ファイルの受け入れ条件が全件 `- [x]` チェック済み
- [ ] 各条件の検証方法が「受け入れ条件の検証方法」テーブルに記載済み

### 3. 成果物

- [ ] 「想定する成果物」に列挙されたファイルがすべて存在する
- [ ] 追加の成果物がある場合は PBI ファイルに追記済み

### 4. リグレッション

- [ ] 既に完了した PBI のテストが引き続き Green

### 5. コンテキスト更新

- [ ] PBI ファイルのステータスが「完了」に更新済み
- [ ] `docs/product-backlog/README.md` の一覧テーブルが更新済み
- [ ] 実装で得た知見が CLAUDE.md または関連ドキュメントに反映済み

### 6. 完了証跡

- [ ] PBI ファイルの「完了証跡」セクションにテスト結果サマリーが記録済み
- [ ] 確認日時が記録済み

### 7. ADR（意思決定記録）

- [ ] 実装中の設計判断を振り返り、記録すべきものは ADR として `docs/adr/` に保存済み
- [ ] 該当 ADR がある場合、`docs/adr/README.md` の一覧テーブルに追加済み
- [ ] ADR 要否の判断理由が PBI ファイルの完了証跡セクションに記録済み（ADR を作成しない場合も「検討の結果不要と判断」等の理由を明記する）

## 適用ルール

- この DoD は全 PBI に共通で適用する
- 受け入れ条件の性質上テストが書けない項目は「手動確認」として検証方法テーブルに明記する
- DoD を満たさない PBI のステータスを「完了」にしてはならない
