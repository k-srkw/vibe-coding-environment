# PBI-18: Feature branch + PR ワークフローの導入

## ステータス: 未着手

## 依存
- なし

## 説明
レトロスペクティブ（PBI の並列作業 P1）で指摘された「全 23 コミットが main ブランチに直接コミットされている」問題に対応する。

現状、ブランチ戦略が存在せず、全ての変更が main に直接コミットされている。複数 PBI を並列で実装する際にコンフリクトリスクが高く、リグレッション検出も手動に依存している。Feature branch + PR ワークフローを導入し、並列作業を安全にする。

## 受け入れ条件
- [ ] PBI 着手時に feature branch を作成するルールが CLAUDE.md に追記されている
- [ ] PBI ワークフロースキル（Phase 1）に branch 作成ステップが追加されている
- [ ] ブランチ命名規則（例: `pbi-NN/short-description`）が定義されている
- [ ] PR マージ前に `npm test` が通ることを確認するガイドラインがある
